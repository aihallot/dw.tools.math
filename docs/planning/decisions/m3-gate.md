# M3 gate decision — numerical/statistical local preview

**Proposed, not yet admitted:** conclude the accepted M3 / 0.4.0-preview only on RS052 durable success. All seven numerical/statistical phase receipts must remain individually authoritative, and the integration release gate must be independently proven.

## Reason and accepted approach

The source phases qualify managed numerical providers, bounded finite matrix algorithms, explicit exact-to-binary64 loss, compensated/exact statistics, typed quantiles/correlations and versioned sampled distributions. Their individual successful runs do not automatically prove a coherent four-package product graph. A separate release gate must cross-check the seven phase identities, all 14 accepted tasks and 42 subtasks, prior M2 gate, compilation and full admitted test suites, managed Math.NET smokes, newly packaged artifacts and a fresh NuGet-only consumer spanning numerics and statistics.

Chosen approach: a read-only C# science/planning validator; six admitted test projects plus foundation verification and three managed-provider corroboration programs; four NuGet packages freshly packed into a single isolated feed; a 31-probe separate consumer with no ProjectReference; and a dedicated archive-only C# SHA-256 helper. Workflow authority hashes remain owned by compiled DWF operations.

The four-product dependency graph is dw.quantities -> dw.tools.math.ir -> dw.tools.math.numerics, plus dw.tools.math.statistics -> dw.quantities. No MathNet.Numerics runtime dependency is introduced into the product graph. No shared version across independently versioned packages is invented.

## Decision, deferrals and honest claims

Successful gate evidence admits a LOCAL 0.4.0-preview. It does not authorize public NuGet publication, a stable product API, full SVD, native BLAS, other unexecuted operating systems/RIDs, universal floating accuracy, cryptographic PRNG, Gaussian distribution tails, general symbolic algorithms or M4 progression. Neither Decision VaR/CVaR/EVPI/MDP nor MCDM PROMETHEE/FlowQuantization/preferences/ranking are Math-owned. The unsent coordination requests remain unsent; no sibling repository adoption is claimed. Neutral dw.discovery attributes, callable skills and AURA BrokerReady are separate, independently testable responsibilities.

Rejected alternative: marking M3 done merely because all its phase statuses are already done, without a fresh independent cross-vertical consumer and observed package artifacts.

The actual package SHA-256 and byte lengths must be computed on the newly built local artifacts only. A previous nupkg hash is not a guarantee that a different SDK rebuild is byte-identical. Gate terminal report and scientific receipt establish the actual runtime and test scope.

**Review triggers:** an actual recipient attempts integration, a new host/RID or native provider is executed, a public package publication is authorized, or the native M4 backlog becomes eligible. M4 symbolic work starts in a separate accepted run; this M3 gate must not advance it.
