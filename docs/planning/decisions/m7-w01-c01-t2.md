# M7-W01-C01-T2 — precision-provider and interval-boundary disposition

## Question

Should Math introduce a high-precision or interval provider now, and can any operation claim outward rounding or real-world uncertainty guarantees? What exact conditions permit a later owner-approved admission or an explicit scoped deferral?

## Observation

- RS106 / `docs/planning/evidence/M7-W01-C01-T1-qualified.json` verified two bounded, independent BCL oracles: exact integer cancellation at `10^16` yields `1` where the particular binary64 calculation yields `0`; an adjacent-double enclosure strictly contains the exact rational `1/10`. These are evidence of representational limits and one exact inclusion, **not** a reusable certified interval computation.
- Math already exposes budgeted `ExactRational` and `ExactBinaryNumber` primitives in `dw.quantities`, and locally qualified finite binary64 analysis/scientific families under the separate M6 gate. No need to remove or relabel these contracts has been proven.
- `docs/planning/decisions/m7-w01-c01-provider-screen.md` lists the BCL/existing exact-rational route, finite `decimal`, managed arbitrary-precision candidates, managed interval candidates, and native MPFR/Arb-class candidates. The latter categories are **unqualified research options**, with no accepted exact provider/version/commit, rights/notices decision, independent rounded-operation corpus, source-free consumer, operating-system qualification, or integration budget.
- No named downstream consumer or accepted Math requirement currently establishes an operation that requires a new dynamic-precision/interval public API rather than existing exact or bounded binary64 contracts. A proposed future primitive is not delivered demand.
- The independent read-only C# T2 checker `docs/planning/ValidateM7PrecisionBoundary.cs` verifies prior T1 source/document SHA-256 pins, explicit non-adoption boundaries, roadmap parity and a negative-gate policy. The original T1 numerical oracle is separately re-executed before T2 state transitions, not mislabeled as newly implemented science.

## Decision — explicitly defer

**DEFER all new third-party high-precision and interval providers and all corresponding public Math APIs.** Retain the existing qualified Math exact and finite binary64 contracts. This is a completed **spike decision**, not a failed gate, a new numerical implementation or permanent prohibition.

The local spike closes with a reproducible *not-admitted* provider matrix and three independent re-entry triggers:

1. **Demonstrated consumer gap:** record a concrete Math-owned operation and caller, known finite domain/limits, a measurable failure of existing exact/binary64 contracts and a clear precision/error target. A mere larger digit count or sensor uncertainty guess is insufficient.
2. **Qualified candidate identity:** provide exact package and source revision, SHA-256, license, transitive/native notices, redistribution permissions, .NET target, actual RID, cost/maintenance review and offline installation/rollback.
3. **Bounded independent acceptance:** run exact rational/reference inclusion and adverse tests for **each proposed operation**, documented outward-rounding mode and precision policy, overflow/NaN/domain and cancellation budgets, typed no-partial refusal, independent source-free consumer and reproducible package identities.

All three triggers are necessary before a future owner-authorized admission; a trigger appearing does not automatically enable an implementation. Reassess through a new DWF decision, with no silent package cutover or new dependency.

## Boundary and integration disposition

- **Arithmetic precision** concerns a finite computation model, not experimental or physical uncertainty.
- **Interval inclusion** requires justified outward endpoints per operation. Two adjacent doubles around one rational are not a certified interval algebra, nor a quantitative global floating-point error theorem.
- **Measured uncertainty** additionally requires an explicit data/error model, calibration, correlation or confidence assumptions. Do not infer it from machine epsilon or arbitrary precision.
- A deferred provider has **no selected license/rights/semver**, no tested RID, no external binary, no Math public interval API, no AURA/Decision/MCDM approval and no published `1.2.0` package.

## Acceptance, cost and next action

T2 is documentary Q/O/D with a read-only C# boundary checker, prior exact T1 provenance and a separately staged release-boundary matrix. **No product API** was implemented, no new provider was qualified, and no existing Math package was modified. The accepted product result is a **deferral with three review triggers**, zero external providers and unchanged APIs. The run does not create an advanced library, change a sibling repository, download a provider, pack NuGet or run a broad benchmark.

After qualified T2 evidence, close the C01 *spike phase* while leaving M7-W01 and M7 active. `M7-W01-C02` (tensors/advanced structures) is the next accepted independent spike; its own consumer evidence and decisions cannot be inferred from this deferral.
