# M0-W01-C02 — DWF adoption and product mapping

## Status

This decision is qualified only when it is committed by a successful RS002 result with the native-adoption validator passing.

## Decision

The accepted product roadmap and the native DWF plan have distinct responsibilities:

- `docs/planning/backlog.json` owns product scope, stable product IDs, dependency meaning, acceptance recipes, and source coverage.
- `.aura/workflow/plan/project.json` owns executable workflow selection and lifecycle progress.
- The native plan is a faithful executable projection of the accepted roadmap, not a reduced second roadmap.

The stable mapping is release -> milestone, work package -> work package, chunk -> phase, task -> task, and subtask -> subtask.

## Structural qualification

The reconciled native plan is validated against the accepted backlog for:

- exact product IDs and parent relationships;
- release and chunk dependency parity;
- 8 milestones, 17 work packages, 53 phases, 106 tasks, and 312 represented subtasks;
- canonical English native titles;
- durable RS001 evidence for the completed C01 phase and its two accepted task responsibilities;
- one documented historical exception for the six C01 RED/GREEN/verification subtasks that DWF never observed individually.

No future accepted subtask is omitted.

## Historical boundary

RS001 completed M0-W01-C01 while the native bootstrap still used coarse task granularity. The durable RS001 result proves both accepted C01 responsibilities, so those two product tasks are projected as done.

The six finer C01 process subtasks are intentionally not backfilled as done. Doing so would invent lifecycle history. This is the only structural omission and is recorded in `native-dwf-roadmap-reconciliation.md`.

## Run-progress contract

A product run must update DWF progress in the same payload that performs its bounded work.

RS002 therefore starts from the exact ready C02 continuation, activates each decision subtask in order, completes its two tasks and phase, and declares an achievement for every node transitioned to done. Exact completed-state re-entry is accepted; any third state is refused.

## Generation and validation boundary

Product planning generation and DWF execution authority stay separate:

- product projection generation is explicit and mutating;
- preparation-safe validation is observational;
- the product planning generator does not fabricate DWF authority;
- no filler run is used to create project structure;
- same-run correction and delivery recovery remain DWF-owned.
