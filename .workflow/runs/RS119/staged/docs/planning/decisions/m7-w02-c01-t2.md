# M7-W02-C01-T2 — formal proof trusted base and toolchain admission decision

## Question

Can the exact polynomial-certificate witness qualified by T1 justify admitting Lean, Rocq, an SMT solver, an independent proof-kernel provider or a public formal API? What exact trusted base, failure status, legal/platform evidence and downstream proof-consumer contract must exist before any such admission?

## Observation — trusted base and falsification

RS118 independently replayed the source-owned fixture `docs/planning/fixtures/m7-polynomial-identity-certificate.json`. For the single identity `(x-1)(x+1)=x^2-1` in `Z[x]`, integer-coefficient convolution gives the exact vector `[-1,0,1]`. The receipt `docs/planning/evidence/M7-W02-C01-T1-qualified.json` pins the fixture, read-only `docs/planning/ValidateM7FormalCertificate.cs`, decision and provider-screen SHA-256 hashes. This is a **locally checked finite algebraic certificate**, not a proof term checked by a Lean/Rocq kernel or an SMT proof replay.

The declared research trusted base is deliberately limited to the exact source-owned JSON schema, the C# coefficient-parsing/convolution verifier, .NET BCL `BigInteger`, the installed .NET SDK and the local filesystem. The source code and runtime are **not a formally certified proof kernel**, and no generic proof checker, axioms, remote verification service or immutable external provider were accepted.

The finite certificate outcomes remain discriminated:
- **verified-finite-identity**: complete fixed `Z[x]` factor/certificate/right-hand vectors pass independent exact replay
- **invalid-certificate**: wrong/truncated coefficient vector or mismatching complete certificate; no proof
- **unproved**: missing witness, hole, unknown provider, timeout or provider failure; never automatically promoted
- **derivation**: an explanation or transformation trace, not independently replayed certificate evidence
- **externally kernel-proved**: **not observed**; would need pinned kernel, accepted proof term and independent execution evidence

Point evaluations, residual tolerance, a provider's `success` response, `SAT/UNKNOWN` status or a process exit code cannot replace a checked proof/certificate. The read-only `docs/planning/ValidateM7FormalBoundary.cs` requalifies both T1 oracle groups, source SHA pins and the no-admission boundary before closing C01.

## Decision — explicitly defer external formal providers

**DEFER Lean, Rocq, SMT proof/certificate provider integration, a general theorem prover, and public Math formal APIs.** Keep only the already qualified *research* JSON identity certificate and its limited C# replay. No kernel, solver executable or redistributable artifact was installed or version/license/TFM/RID qualified. No source-free recipient or public package was admitted.

Three mandatory **re-entry triggers**, all independently required before a future owner-approved implementation decision:

1. **Real proof consumer and exact domain**: name a concrete Math/Decision/client proof question, explicit `Z[x]`-like language/axioms/term semantics, certificate/proof export format, assumptions and why existing Math exact computation is insufficient.
2. **Trusted base and finite refusal contract**: pin the kernel or independently sound checker, its accepted axioms/rules, source/version and build; document invalid/hole/unknown/timeout/provider failure as unproved, no partial proof, cancellation/deadline, certificate-size/time/memory budgets, and independent malicious/negative fixtures.
3. **Source, rights, platform and recipient evidence**: exact source commit/artifact SHA, license and transitive/native notices, redistributable terms, `net10.0` and Windows/Linux/RID support as required by a named consumer, reproducible offline install/replay, rollback and a **source-free consumer**, with explicit approval by Math and the owning client.

**All three review triggers are necessary, not automatic approval. If any is missing, remain deferred.** Research completion is not a permanent ban and does not authorize a home-grown prover as a workaround.

## Ownership, evidence and stop-loss

Math may own a *qualified, explicitly bounded certificate data contract*, not a generic verification operating system. AURA owns command execution, agent scheduling, permissions, cost monitoring and provider brokerage; Decision/MCDM retains its own problem/consumer contracts. No siblings or workflow mechanics are modified.

The independent T2 gate `docs/planning/ValidateM7FormalBoundary.cs` checks historical SHA-pinned T1 sources, immutable finite identity, negative result statuses and retained C01/C02/M7 lifecycle boundaries, then checks exact T2 receipt pins after DWF mutation. The original research certificate is rerun **before** changing phase state; T2 does not claim a second new theorem.

No public `dw.tools.math.formal` library, Lean/Rocq/SMT plugin, full source-free consumer, theorem proving service, native provider or published NuGet is delivered. Keep formal interoperability as research until a named client can justify a provider.
