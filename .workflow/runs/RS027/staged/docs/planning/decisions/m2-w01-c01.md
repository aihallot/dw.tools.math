# M2-W01-C01 — Minimal mathematical IR: alternatives, semantic boundaries and scope

## Decision

**Accepted as a bounded architecture decision, not an implemented IR library.**

Choose an immutable, typed, provider-independent AST owned by a future
`dw.tools.math.ir` project. It must preserve exactness, quantity semantics,
variable identity, domain restrictions and admitted operation identity without
attempting to become a universal symbolic language. Its internal identity and
a later canonical JSON codec are distinct from presentation, source grammar and
third-party interchange formats.

This decision enables `M2-W01-C02` to establish RED/GREEN contracts. No M2 IR
assembly, encoder, parser, symbolic simplifier, matrix engine, OpenMath
serializer or MathML serializer is delivered by this architecture spike.

## Researched standards and candidate assessment

Standards considered as of 2026-10-09:

- **OpenMath 2.0 revision 2** (OpenMath Society normative standard):
  https://openmath.org/standard/ ; abstract objects, symbols with content
  dictionaries, application and binding. Its published CDs can express
  interoperable meaning, but Math still needs internal typed quantities,
  budget limits and ownership of domain assumptions.
- **Content MathML** (W3C MathML 4 Working Draft dated 2026-10-08):
  https://www.w3.org/TR/2026/WD-mathml4-20261008/ ; content markup separates
  mathematical meaning from display, and **Strict Content MathML** aligns with
  OpenMath objects. A working draft is not adopted as a frozen output ABI.
- **Native typed AST**: direct `.NET` immutable discriminated node model
  preserving `dw.quantities.ExactRational`, eight-dimensional quantities,
  explicit scopes and restrictions. Selected because exact semantics and
  narrow validation are controllable without third-party runtime dependency.
- **Provider-specific AST** (CAS/numeric framework): rejected as canonical
  because it couples the public Math model to an optional engine, implicit
  precision, assumptions or proprietary node semantics.

OpenMath and Content MathML are **future import/export adapters over an
explicitly admitted subset**, not byte-equivalent substitutes for the
canonical JSON planned in `M2-W01-C03`. Semantic normalization and
interchange loss must always be reported; no arbitrary OpenMath dictionary
or MathML construct is silently accepted.

## Mandatory fidelity/loss matrix

The machine-readable, independently reviewable matrix is
`docs/planning/evidence/M2-W01-C01-mapping.json`, with the following
contractual interpretation. **No row asserts a working serializer.**

| Case | Native IR representation | OpenMath mapping (candidate) | Strict Content MathML mapping (candidate) | Loss/guard |
|---|---|---|---|---|
| `1/3` | `ExactRational(1,3)` | `OMA(arith1.divide, OMI(1), OMI(3))` or agreed rational symbol | `apply(csymbol arith1:divide,cn integer 1,cn integer 3)` | Exact numerator and denominator must survive; never silently become binary64 |
| `1 inch` | `Quantity(ExactRational(1,1), imperial.inch, Length, absolute=false)` | value plus explicitly versioned unit CD identifier | value/application plus explicit unit `csymbol` identifier | Standard content vocabularies do not automatically carry Math's 58-unit IDs/profiles, affinity or display policy; report unsupported mappings |
| Rectangular 2×2 matrix | finite ordered `Matrix` with 2×2 shape and typed entries | agreed matrix constructor CD only | `matrix` in full markup or explicit strict `apply/csymbol` | Ragged/oversize shapes reject; no silent provider-specific matrix class |

| `(x²−1)/(x−1), x != 1` | `Apply(divide,...)` with explicit `Exclude(x,1)` assumption referring to a stable symbol identity | expression and separate attributed condition when admitted by negotiated CD | expression with separately encoded assumption/annotation when admitted | Simplifying to `x+1` without retaining `x != 1` loses domain and is forbidden |

See also the adjacent independent symbolic contract `sqrt(x²)=|x|` over
reals (not `x` absent `x>=0`); this is a **future rewrite guard**, not
proof that an M2 solver exists.

## Proposed admitted IR core

Use a closed, immutable discriminated-node hierarchy (names provisional
until compiled contracts):

1. `ExactScalar`: reuse `dw.quantities.ExactRational` (canonical
   numerator/positive denominator and `default` = 0/1). No new
   `BigRational` implementation, implicit conversion to `double`,
   unchecked narrowing or rounding-based semantic equality.
2. `ApproxScalar`: an **explicit** IEEE-754 binary64 payload preserving
   the received finite bit pattern, with kind identity distinct from an exact
   rational. Do not turn a floating approximation into an exact decimal
   without a requested conversion policy.
3. `QuantityLiteral`: an exact/approximate value, canonical unit ID,
   eight-component `DimensionVector`, transform/temperature semantics and
   an explicit resolved `UnitSystem`. A dimension alone is insufficient
   to recover original source unit or absolute-vs-interval temperature.
4. `Symbol`: stable internal symbol identity, `Free` or
   `Bound(scopeId,slot)`, and an optional passive display label.
   Two identical text labels from different scopes are not identical
   variables. All transformations must be alpha-aware and capture-free.
5. `Apply`/`Relation`: closed, namespaced operation IDs, typed argument
   lists and declared arities (`add`, `multiply`, `divide`,
   `power`, `root`, `abs`, `min`, `max`,
   `equal`, `notEqual`, selected comparisons). No arbitrary
   executable registry, delegate injection, C# execution or automatic
   simplification.
6. `Matrix`: finite rectangular ordered shape, positive bounded rows and
   columns, homogeneous admitted element types and defensive immutability.
   Future numeric providers translate from this public shape, not vice versa.
7. `Domain`/`Assumptions`: declared real/complex/integer domain and
   explicit predicates/restrictions tied to symbol IDs and expression
   identities. In particular, nonzero divisors and exclusions survive every
   transformation.

A prospective finite budget policy is `MaximumNodes=1024`,
`MaximumDepth=32`, `MaximumIdentifierCharacters=128` and
`MaximumMatrixElements=4096`. These are **proposed next-chunk guards**;
no execution or serialization enforcement is claimed here. The exact
source grammar has its own independent 4096-character/256-token bounds
and must not be mistaken for the IR validator.

## Policies and rejected extensions

- **Exact vs approximate**: implicit widening is disallowed. Binary64 NaN
  and infinities are **not admitted into v1 ApproxScalar**; reject them with
  a typed diagnostic. Preserve finite `-0.0` bits when that is part of a
  declared approximate transport contract.
- **Complex**: defer generic complex and branch-sensitive operators; a
  later ADR must define a complex principal branch explicitly. No arbitrary
  implicit real-to-complex coercion.
- **Intervals**: defer generic interval arithmetic; absolute temperature
  vs temperature interval is an admitted semantic tag, *not* an interval
  analysis type.
- **Binding/capture**: nested scope identities are mandatory before lambda,
  substitution, summation or quantifiers may be admitted. Textual names
  alone never define binding.
- **Domain**: `sqrt(x²)` over reals retains `|x|`; rewriting to `x`
  needs `x>=0`. `(x²−1)/(x−1)` cannot be simplified to `x+1`
  unless `x != 1` remains attached.
- **Immutability/cost**: defensive copying of input collections, cycle
  rejection, bounded tree traversal, checked shape multiplication and size
  limits before allocation. BigInteger is not a license for unbounded work.
- **Interoperability**: no claim of universal OpenMath/MathML round trips,
  full content dictionary support, or syntax-preserving formatting. Future
  adapter reports `exact`, `conditional`, `lossy`, `unsupported`.
- **Semantic hashing**: reserve a versioned canonical **structural**
  digest for M2-W01-C03, distinct from presentation hashes and any proof
  of arbitrary mathematical equivalence. No hash codec is implemented now.

## Decision on BigRational

**Reuse the already-qualified `dw.quantities.ExactRational`.** It has
`BigInteger` numerator/denominator, positive canonical denominator,
exact operators and an explicit default-zero representation. A second
`BigRational` type would duplicate core invariants and create ambiguous
conversion/equality boundaries. Introduce a wrapper *only* if C02 tests
demonstrate necessary IR node metadata; such a wrapper delegates the exact
value without redefining arithmetic.

## Acceptance and next execution

`M2-W01-C01` completes **as a documented spike** only when the ADR, the
five-case machine-readable mapping, the independently checked decision
schema, and both decision-task evidence stages are present. Product
implementation begins at `M2-W01-C02`, with separately executable REDs
for bound/free symbol identity, exact/approximate separation and
`sqrt(x²)` restrictions. The canonical JSON and unknown-version
rejections follow in `M2-W01-C03`. No provider or binary package is
declared delivered by this decision.

Authority is limited to the Math repository; external AURA package
adoption remains the untransmitted draft in
`docs/coordination/requests/MATH-XR-002-aura-adoption.json`.
