# M0-W02-C02 — package identities, localization, and UnitConverter boundary

## Status

**Accepted for the initial transfer.**

This decision freezes the M0 transfer shape. It does not copy source yet; M1 performs the actual extraction against the pinned manifest.

## Package identities

Initial transfer preserves the inherited package identities and namespaces:

- `dw.quantities`
- `dw.quantities.expression`
- `dw.quantities.standard`

Changing ownership and changing the public model are deliberately separated. New `dw.tools.math.*` packages are introduced later only when a proven capability requires them.

The package graph is standalone:

- `dw.quantities` has no AURA dependency;
- `dw.quantities.expression` depends only on the exact-quantity layer it needs;
- `dw.quantities.standard` may depend on the quantity/expression packages but **not** on `dw.localization` or an AURA checkout.

## Localization decision

Two options were considered:

1. transfer the shared `dw.localization` package into Math;
2. keep only passive language metadata in the standard-unit catalog.

Option 2 is selected.

Math owns mathematical unit data, aliases, and passive language-tagged names. The initial contract uses BCL-only strings/collections and canonical language-tag strings. It does not import the localization framework or presentation preferences.

AURA keeps `dw.localization`, `MathCultureResolver`, the AURA-facing `UnitCatalog` facade/projection, `UnitLocalization`, and `UnitProjection`. AURA may adapt passive Math metadata into its localization types on its side.

## UnitConverter boundary

Math owns pure source -> base -> target conversion through unit definitions and exact quantity semantics.
The raw AURA `UnitConverter.cs` file is a behavioral adaptation source, not a mandatory byte-for-byte transfer.
AURA keeps command-facing validation, localized errors, culture selection, projection, permissions, and host policy.

## Transfer manifest

The exact classification is recorded in `docs/planning/evidence/M0-W02-C02-transfer-manifest.json`, including pinned SHA-256 values, target roots, transferred tests, adaptation sources, and retained host files.

## External compatibility

This decision changes no Decision or MCDM API and writes to no external repository.

## Consequence

`EXT-LOCALIZATION` is satisfied for the planned extraction architecture.
Actual source copying remains future M1 work and must re-check every pinned SHA-256 before transfer.
