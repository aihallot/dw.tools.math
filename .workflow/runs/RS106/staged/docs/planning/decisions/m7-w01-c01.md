# M7-W01-C01-T1 — bounded precision and interval research admission

## Question

Does Math need an additional precision/interval provider beyond existing `dw.quantities.ExactRational`, `ExactBinaryNumber` and the local M6 binary64 kernels? Which exact finite examples distinguish arithmetic representation, rounding, numerical conditioning and physical measurement uncertainty? What evidence would justify a new package without promising universal certified bounds?

## Observation

The accepted M6 local G-M6 milestone is done (see `docs/planning/evidence/M6-gate.json`), but its finite binary64 accuracy reports are not rigorous universal error enclosures. The existing `dw.quantities` exact-rational and binary-value contracts already preserve exact numbers; they do **not** supply arbitrary-precision transcendental evaluation or generally certified interval arithmetic.

The independent, BCL-only oracle program `docs/planning/ValidateM7PrecisionAdmission.cs` checks two deliberately narrow cases **at RS106 execution**, not at document-authoring time:

1. **Cancellation and sensitivity:** let `a = 10000000000000000`, `b = 1`, `c = a`. The mathematical integer result `(a + b) - c = 1`, independently evaluated using `BigInteger`. Evaluating `(a + b) - c` in binary64 returns `0` because the spacing at `a` is `2` and adding `1` rounds away. The example is cancellation-sensitive (input magnitudes far exceed output); no general error theorem is inferred.
2. **Reference rational inclusion:** `1/10` is exact as an integer ratio but not representable by finite binary64. Decode the exact binary ratio of `double 0.1` and the adjacent predecessor `double.BitDecrement(0.1)` with `BigInteger`; independently verify `predecessor < 1/10 < 0.1`. This constructs a witness enclosure for **this single constant**, not a reusable outward-rounded interval computation or a bound for any measurement.

The two observations show distinct questions: (a) whether more precision is needed to preserve computation in a declared model, and (b) whether a rounded interval contains a mathematically specified reference. Neither supplies data about sensor calibration, statistical confidence, input uncertainty, correlation or physical error.

`docs/planning/decisions/m7-w01-c01-provider-screen.md` compares candidate approaches and explicitly marks all new providers as **unqualified**. No external package has been downloaded, version-pinned, licensed, benchmarked or accepted for this task.

## Decision

**Admit research fixtures only**: the narrow BCL reference oracles, provider evaluation criteria and reproducibility boundaries above. Keep existing exact-rational/binary-value and binary64 APIs as the delivered local baseline. Defer selection of any new high-precision real, rounding-mode or interval public contract until independent T2 provider qualification. In particular, do not add a new production library or promise a certified interval implementation based on binary64 epsilon.

Proposed conditional next subset if evidence justifies it: a finite-input, explicitly budgeted precision policy and a bounded interval-result contract that declares endpoint semantics, directed-rounding provenance, supported operations, failure status, provider revision, target runtime and the difference between arithmetic enclosure and physical measurement assumptions. This is a **proposal for a future ADR**, not an admitted implementation.

## Alternatives and budget

- Reject silently replacing `ExactRational` with `double` or `decimal`; fixed decimal precision is not arbitrary precision.
- Reject treating adjacent-double bracketing of one rational constant as a rigorous interval engine.
- Reject new native binaries or unlicensed managed dependencies before reproducible, offline source/provider and redistribution qualification.
- Scope the local research to two cases, one BCL-only script, two documents, one read-only oracle run and ordinary planning validators. No general performance benchmark, new scientific package, cross-repository source read, CI or provider installation.

Do not equate calculation precision, certified arithmetic enclosure, empirical numerical error or real-world uncertainty.
