# M6-W02-C05-T1 — admitted scientific family contracts and owner-gated reuse

## Question

Which scientific capabilities are actually admitted by durable DWF evidence,
with independent oracles, finite domain boundaries and provider/source pins?
What precisely should be proposed to `aihallot/dw.tools.decision` for potential
deduplication, without assuming that a duplicate exists or causing cutover?

## Observation

This is a **documentary** adoption/qualification gate, NOT a new scientific
implementation or an automatic external adoption. The current product
baseline is RS102: scientific local preview `1.1.0-preview.14`,
actual archive SHA-256
`2de3e9f536ced58e28d1558ff7c4692f367b72d5efaa1989d56ffa8ec07a31cf`,
37,270 bytes, seven independently restored source-free eight-probe clients;
90 T2 GREEN plus 904 prior scientific tests and four Math regression
projects. These are RS102 observations, NOT tests newly run by RS103.

Seven independently admitted family/boundary contracts are documented in
`docs/distribution/m6-scientific-family-adoption.md`; the manifest of
origin is each separately delivered `docs/planning/evidence/*-qualified.json`.
Historical preview identities remain as delivered — never rewrite the
original family evidence as if all variants were initially approved by
preview.14. The latest package receipt only establishes cumulative
local binary/source-free regression for the observed clients.

The proposed Decision deduplication **assessment**, not a confirmed duplicate,
is `docs/planning/requests/decision-bounded-bracketed-root-assessment.md`.
It identifies one bounded scalar bracketed-bisection primitive used by
financial IRR, the expected deterministic contract, oracles and stop
conditions. Decision's owner must inspect whether this is genuinely useful
in that repo; no cross-repository write, package cutover, or license
assertion is part of this document.

## Decision

Publish the seven-family local adoption matrix and the one scoped,
owner-gated Decision assessment request as documentation. Preserve
`dw.tools.math.scientific` as the qualified provider; retain the
historical evidence/provenance and cross-family numeric limits. Do not
move an implementation because a suggestive shared name appears.

No cross-family functionality is removed, no public package is published,
no AURA/Decision/MCDM integration is certified, and no runtime
`dw.discovery` exposure is invented by this document. Any real
deduplication requires an explicit owner decision, stable API/revision
pinning, semver and notices review, independent consumer verification,
and a separate DWF delivery.

The acceptance of this **T1 document task** is:
(1) source/evidence SHA-256 pins and independent numeric oracle for
every admitted family; (2) consumer test or source-free receipt pointer,
domain limits, and provider version; (3) precisely one review request
naming its candidate primitive, interface and explicit nonclaims;
(4) native DWF Q/O/D completion and project-planning parity.
C05-T2 and C05, M6-W02 and M6 remain **unfinished**.

## Alternatives rejected

- Automatic library extraction or renaming based on conceptual similarity.
- Treating conservative binary64 risk heuristics as certified error theorems.
- Treating per-family historical previews as a present public release.
- Invoking internet data providers or modifying `dw.tools.decision` in this run.
