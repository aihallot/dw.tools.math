# M7 S02 — finite PlotModel no-renderer admission gate

**Disposition: DEFER** a public PlotModel, chart drawing, adaptive numeric sampling and third-party provider. The size-M S02 spike closes through a documented Math/client ownership decision, not by delivering a runtime.

## Historical independent reciprocal witnesses

| Reference | Proven finite behavior | Unqualified expansion |
|---|---|---|
| `[-2,-1,0,1,2]` | Four finite points, two disconnected segments, one recognized pole gap and one break | No line across zero or inferred pole point |
| `[-2,-1,1,2]` | Four finite points, two segments, **one break** despite omitted zero | No silent interpolation across an unobserved known singularity |
| Eight-sample grid | `[-4,-3,-2,-1,1,2,3,4]`, exactly 8 finite points and 2 segments | Not a full plot/scene or generalized sampler |
| Invalid grid/outputs | Missing/duplicate/descending/nonfinite input; tiny finite x yields infinite reciprocal | Refuse; no partial points/segments |
| Research limits | **8 samples / 8 points / 2 segments** | No audited memory, cancellation or performance budget |
| Illustrative storage | 8 points × 2 binary64 coordinates × 8 bytes = **128 coordinate bytes** | Array/container/temporary overhead excluded; not a product byte SLA |

The BCL-only `docs/planning/ValidateM7PlotSampling.cs` is a study oracle. No certified general continuity, monotonic interpolation, error interval or physical measurement uncertainty is inferred from it.

## Ownership and candidate screen

| Responsibility | Disposition | Remaining qualification |
|---|---|---|

| AURA/client UI renderers and job/permission handling | **AURA/client-owned; do not copy** | Separate ownership acceptance and actual consumer-side implementation |

These are research categories, not evaluated package selections.

## Three mandatory review triggers

1. **Consumer and domain:** a named Math caller, finite function/domain, singularity assumptions, monotonic sample-grid input and exact point/segment output semantics missing from current APIs.
2. **Resource and failure contract:** explicit finite sample/point/segment and *total allocation* byte limits, known discontinuity segmentation, invalid/nonfinite refusal, cancellation/deadline, no hidden copies and typed partial-output rules.
3. **Provider/source-free recipient authority:** immutable source/version/rights/notice and .NET RID proof when a provider is proposed, adverse oracle corpus, rollback cost, isolated source-free consumer and explicit Math + AURA/client owner approval.

**If any review trigger is missing, remain deferred.** Three triggers never automatically authorize a package or renderer.
