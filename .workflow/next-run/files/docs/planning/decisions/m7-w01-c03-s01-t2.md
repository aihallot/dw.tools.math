# M7-W01-C03-S01-T2 — pure DAG ownership, resource and provider disposition

## Question

Do RS111's reproducible four-node pure diamond and negative oracles establish demand for a public Math DAG evaluator or AURA scheduling integration? What independent caller, identity, cancellation, resource and provider evidence would justify one, without turning a completed research spike into a delivered engine?

## Observation

- RS111's immutable `docs/planning/evidence/M7-W01-C03-S01-T1-qualified.json` and SHA-pinned BCL-only `docs/planning/ValidateM7DagAdmission.cs` establish `shared=2`, `left=5`, `right=8`, `root=13` for a diamond with four nodes and four edges. Shared is evaluated exactly once; maximum observed path is three nodes.
- The research corpus refuses directed cycles and self-loops, unknown or duplicate identities, malformed operation arity, more than eight nodes, more than ten edges and paths exceeding depth four. Checked arithmetic overflow returns **no partial result**. These are bounded **study oracle budgets**, not a public product's performance, cancellation, thread-safety or numerical guarantees.
- The structural predecessor `docs/planning/evidence/M7-W01-C03-split-qualified.json` keeps the original size-L C03 aggregate planned and S02 PlotModel separately blocked behind S01. No independent PlotModel discontinuity, segment renderer or graph runtime has yet been accepted.
- The owner screen `docs/planning/decisions/m7-w01-c03-s01-owner-screen.md` distinguishes mathematical nodes from AURA agents, task/job scheduling, resource quotas, rendering, remote execution and permissions. The tested pure graph is a local BCL reference, not an installed library, NuGet API or source-free consumer.
- There is currently no named Math consumer with an admitted operation, aliasing policy, provider provenance and independent isolated package consumer demonstrating the need for a new runtime API rather than existing Math functions.

## Decision — explicitly defer public DAG runtime

**DEFER** introduction of a new public DAG evaluation API, managed/native graph engine, asynchronous scheduler or shared mutable work graph. Retain existing Math functions and the finite pure DAG reference *only as research evidence*. This closes S01 as a **research spike**, not as a product feature or permanent prohibition.

Three mandatory **review triggers** must all be met before future owner-authorized admission:

1. **Demonstrated consumer gap:** identify one actual Math caller, immutable supported node/operation set, source/result domain, a reproducible shared-computation need and why existing exact, numerical or symbolic APIs are insufficient.
2. **Bounded semantics and failure policy:** specify graph identity and duplicate/alias semantics, pure memoization, deterministic topological order, independent cycle and unknown-reference refusals, checked overflow, cancellation and deadlines, finite node/edge/depth, memory, output and recursion budgets. Reject partial results on refusal; no fallback to impure callbacks or automatic remote execution.
3. **Independent provider and recipient qualification:** for any new managed/native engine, pin exact source revision/package SHA and version, license/rights and transitive notices, `net10.0` target/RID, offline restore/rollback and maintainer cost. Qualify typed error statuses, adversarial pure-DAG oracles, reproducible source-free package consumption and explicit owner/recipient approval.

**All three triggers are necessary** but none independently grants permission or proves a generally safe graph runtime. Without them, the decision remains **deferred** with an explicit review trigger.

## Math/AURA boundaries and negative claims

Math may own a pure mathematical representation or future deterministic numerical graph calculation only after separate scope admission. **AURA owns** task scheduling, execution queues, agent calls, workflow orchestration, transport, resource governance, permission policies and UI presentation. PlotModel point/segment **data** belongs to the later S02 research; actual chart rendering is not admitted to Math.

No public DAG API, `dw.tools.math.advanced` package, third-party graph provider, AURA scheduler copy, `dw.discovery` activation, Decision/MCDM migration, additional RID, asynchronous engine, distributed executor or published NuGet was delivered. The `8 nodes / 10 edges / depth 4` limits do not become public supported bounds or an arbitrary-precision guarantee.

## Local acceptance, cost and next action

The independent read-only `docs/planning/ValidateM7DagBoundary.cs` verifies RS111 SHA-pinned reference sources and semantics, the three admission triggers, the original split plan, C03/S02 non-delivery and the exact native/product transition. RS112 reruns the two RS111 oracle groups before completing T2, without claiming new product tests or consumer qualification.

On successful RS112, **S01 and its T2 Q/O/D substages become done**, while original C03, S02, W01 and M7 remain incomplete. The next admissible independent research is S02-T1, with bounded `1/x` discontinuity sampling and segment breaks. No graphical rendering or AURA job engine is part of that next scope.

**Stop-loss:** one staged BCL checker, this decision and the bounded distribution screen, targeted planning validation. No broad benchmark, package installation or sibling edits.
