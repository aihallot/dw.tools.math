# G-M4 — Local exact symbolic preview admission

## Decision boundary

M4 owns an accepted LOCAL 0.5.0-preview mathematical responsibility,
not a public or stable 1.0 release. After M4-W01 and M4-W02 are
durably complete, the milestone still needs one independent scientific
gate. RS065 qualifies exactly that gate; the product does not gain an
unbounded symbolic CAS, mandatory provider runtime or agent broker.

## Accepted scientific corpus

The six accepted M4 phases, their 12 tasks and 36 subtasks must be
complete in BOTH docs/planning/backlog.json and the native DWF plan:

- W01-C01: independently observed symbolic provider candidates and
  isolated host/assumption/cancellation limitations, no product CAS
  parser or provider type bridge.
- W01-C02: typed rational-cancellation IR with x != 1 kept at the
  original removable point; rejected untyped/opaque provider results.
- W01-C03: bounded exact expand, factor, substitution and real
  sqrt(square(x)) rules; soft in-process limits are not hard deadlines.
- W02-C01: exact formal real polynomial differentiation and typed
  pointwise nondifferentiability/domain refusals.
- W02-C02: bounded exact real elementary solution sets and separate
  original-equation candidate verification, excluding spurious poles.
- W02-C03: bounded exact rational polynomial primitives, finite limits,
  original simple poles/removable limits and explicit unknown convergence.

All six final phase receipts remain individually authoritative.
The M4-W02 aggregate, prior M2 and M3 gates and W01 provider research
must remain compatible. No historical status is manufactured.

## Gate experiment and distribution boundary

A read-only .NET 10 validator inspects all phases, tasks, subtasks,
prior receipts and release identities without mutating authority.
Run a locked full .NET solution build, focused symbolics/IR/quantities
checks first, then the complete seven-project test suite because this
is a true milestone trust boundary. A separate NuGet-only consumer
proves 32 independent oracles across W01 and W02 through exactly one
pinned local symbolics 0.5.0-preview.10 PackageReference.
It has no ProjectReference, direct foreign provider dependency, remote
feed or bundled AURA/Decision/MCDM code.

Pack three local products (dw.quantities, dw.tools.math.ir and
dw.tools.math.symbolics) in one ignored local feed. Independently
inspect their actual net10 assemblies, nuspec IDs/versions, direct
dependencies, byte sizes and SHA-256. Do not reuse earlier artifact
hashes as predictions or modify DWF hash authorities.

Upon durable gate success, store the actual scientific and packaging
receipts in docs/planning/evidence/M4-gate.json, advance native M4
in-progress -> done, update canonical backlog 0.1.63 -> 0.1.64 and
regenerate product projections in the SAME controlled run. The active
milestone cursor becomes null; M5 remains planned/not-ready.

## Explicit nonclaims

- No public NuGet publication, stable 1.0 product or irreversible
  licensing decision; local package archives remain local.
- No unrestricted CAS, foreign symbolic provider decoder, arbitrary
  solver completeness, complex branches, irrational-root algebraic
  types, numerical integration or implicit domain elimination.
- No AURA/Decision/MCDM/dw.discovery consumption, generated agent
  skill, broker permission or transferred external adoption.
- No certified Linux/macOS or unobserved RID result and no general
  preemptive in-process deadline/secure sandbox.
- No assumption that a SHA-256 of a single local package is a
  cross-machine bitwise reproducibility guarantee.

The following accepted work after a successful local M4 gate is M5's
first independently scoped parsing/interoperability slice, not an
automatic Math release or change to sibling repositories.
