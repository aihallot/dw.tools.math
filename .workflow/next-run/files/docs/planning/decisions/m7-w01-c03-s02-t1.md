# M7-W01-C03-S02-T1 — finite reciprocal PlotModel discontinuity research

## Question

What minimal, finite point/segment representation can Math study for the reciprocal function `f(x) = 1/x` while rejecting invalid samples and ensuring no line segment bridges the pole at `x = 0`? Which numeric and resource limits can be independently checked without introducing a renderer, adaptive sampler, or AURA execution engine?

## Observation — independent finite reference

The prior S01 DAG research ended in a locally qualified, owner-gated deferral under `docs/planning/evidence/M7-W01-C03-S01-T2-qualified.json`. The original size-L `M7-W01-C03` aggregate remains planned; the explicitly dependent size-M `M7-W01-C03-S02` is now eligible to study PlotModel **data**, not rendering or job orchestration.

The BCL-only, read-only `docs/planning/ValidateM7PlotSampling.cs` checks a fixed uniform-looking *declared* input grid `[-2, -1, 0, 1, 2]`, with no interpolation or inferred sampling cadence. The exact hand-computable reciprocal values are `[-1/2, -1]` and `[1, 1/2]`. Because `x=0` is undefined, the accepted result has **two disconnected segments**, **four finite points**, **one pole gap** and **one segment break**. No connection is allowed between `(-1,-1)` and `(1,1)`.

A second reference grid `[-2, -1, 1, 2]` deliberately **omits zero**: the sampler must still return two disconnected segments and one break, not falsely draw a line across the unobserved pole. The segmentation rule here is explicitly tied to the **known reciprocal pole at zero**; it does not detect arbitrary discontinuities or unknown domain restrictions.

A third reference reaches a declared research-only **8-sample / 8-point / 2-segment cap** with `[-4,-3,-2,-1,1,2,3,4]`. Over-cap, reversed/duplicate, nonfinite-abscissa, insufficient-point and extremely small finite abscissa yielding nonfinite reciprocal output are refusals, with **zero exposed partial results**. Finite output is required; `x=0` is a recognized gap, not an accepted reciprocal value or a general NaN policy.

## Decision

**Admit reproducible PlotModel point/segment research fixtures only**, comprising explicit finite input samples, segment-break markers, known-pole topology and conservative resource refusal. No public PlotModel, Plot API, chart renderer, adaptive sampler, streaming protocol or physical-domain inference is delivered. The existing Math/DAG numerical contracts remain unchanged and no dependency on AURA is introduced.

The next T2 decision must independently qualify a declared finite function/domain policy, points/segments/bytes budget, monotonic grid, cancellation, invalid input, nonfinite output, and whether partial results are allowed only by explicit typed policy. A plot data model must remain separate from rendering, labels and UI orchestration.

## Alternatives and cost

Reject silent polyline bridging across zero, inventing an asymptote coordinate, using absolute epsilon to assert continuity, automatically resampling arbitrary functions or treating the research fixture as a proof of generally safe plot interpolation. Do not copy AURA's job scheduler, graphics toolkit, permissions, chart rendering or resource orchestration.

T1 uses one local C# BCL oracle, this Q/O/D document and an explicit ownership matrix; one independent two-group oracle run and structural DWF checks. No new NuGet, external provider, product project, broad benchmark or paid CI is admitted.

## T2 review trigger and lifecycle

For a public mathematical PlotModel later, require a real consumer, exact finite function/domain, sample-grid and discontinuity semantics, per-point/segment memory quotas, typed refusal/cancellation statuses, independent source-free Math-package consumer and owner acceptance. Otherwise **defer with a review trigger**. The parent C03 and the M7 gate cannot be closed from T1.

After RS113 success, `M7-W01-C03-S02-T1` and its three Q/O/D children are **done**, while S02 remains **in-progress**; S02-T2, parent C03, M7-W01 and M7 remain incomplete. There is **no product PlotModel renderer**.
