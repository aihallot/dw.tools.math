# M7-W01-C03-S01-T1 — pure bounded diamond-DAG research

## Question

Does a Math-owned *pure* expression DAG need to share a referenced value exactly once, reject directed cycles before evaluation, and expose finite node/edge/depth budgets? What independent observations justify a later contract without importing AURA's job orchestration or claiming a shipped DAG engine?

## Observation and independent reference

The accepted size-L split `docs/planning/evidence/M7-W01-C03-split-qualified.json` introduced `M7-W01-C03-S01` (pure DAG study) and its subsequent dependent PlotModel `M7-W01-C03-S02`. The original C03 aggregate remains planned, while S01 was activated for this research only. The earlier M7 C02 tensor provider was deferred; it does not become a graph provider.

The local BCL-only read-only `docs/planning/ValidateM7DagAdmission.cs` validates one independent finite four-node diamond:

```text
      shared = 2
       /     \
left=shared+3   right=shared*4
       \     /
  root=left+right=13
```

Four **distinct pure nodes** and four dependency edges are admitted. The reference evaluator must compute **shared exactly once**, visit each other node once, and produce `left = 5`, `right = 8`, `root = 13`. Maximum graph path depth (nodes) is **3**. The result is an exact bounded integer witness, not a general math expression engine.

Independent invalid cases must **refuse before arithmetic evaluation**, returning no result and evaluated-nodes count `0`:
- directed cycle (`a -> b -> a`) or direct self-dependency;
- unknown dependency or duplicate node identity;
- more than **8 nodes** or more than **10 dependency edges**;
- dependency path exceeding **4 nodes**;
- unsupported operation shape, and checked arithmetic overflow.

These node/edge/depth caps are *internal research oracle limits*, not public API claims. Numeric source bytes, provider/version and actual runtime are recorded by the DWF run, not invented from the document.

## Decision

**Admit the bounded pure DAG reference/oracle corpus only.** Retain existing Math computations. A candidate future operation DAG would be immutable and side-effect-free, with explicit node identity, dependency ordering, numeric domain, cancellation/budgets and typed statuses. Its computational representation is separate from a scheduler, parallel execution service or visualization renderer.

No public DAG or graph evaluator product API is implemented in T1. The BCL reference is a test/decision tool only. No `dw.tools.math.advanced` package, AURA job engine, GPU/runtime provider, thread scheduler, graph renderer or cross-repository migration is authorized.

## Alternatives and resource stop-loss

- Reject copying AURA's agent/task orchestration or assuming shared graph identity implies a caching guarantee for impure callbacks.
- Reject a single diamond example as proof of all DAG complexities, cancellation semantics or arbitrary precision.
- Reject large graph benchmark campaigns, cycle recovery as a partial success, automatic streaming and hidden allocation.
- Limit T1 to one small source-free BCL script, two planning documents, exact graph/refusal oracles and structural DWF planning checks. No new production source or paid CI.

## Next decision — S01-T2

Qualify graph provenance, finite input/output and error budgets, duplicate/reference alias policies, immutable contract semantics, owner boundary, cancellation, failure/no-partial-result results, and exact source/version/licensing for any proposed new provider. T2 may explicitly defer the runtime API with a review trigger if no consuming Math operation is demonstrated. Independently qualify S01 before activating S02; the PlotModel's `1/x` discontinuity remains untested here.

**Lifecycle:** after successful RS111, S01 and M7-W01 remain in-progress; T1 and its Q/O/D substages are done, S01-T2 and S02 remain not-ready, the original size-L C03 stays planned/not-ready, and M7 remains in-progress.
