# M4-W01-C01 — symbolic provider qualification decision (T1)

**Qualification status:** RS053 proposal, not a delivered symbolic library. Only a successful DWF report and observed scientific evidence admit the T1 spike and its A/B/C tasks. C01-T2 and M4-W01-C02 remain planned.

## Question: what can be accepted without changing a mathematical domain?

The first accepted provider subset is conditional simplification of a removable singularity, an elementary polynomial derivative, and two independent real-root cases. A visually simpler printed expression does not prove mathematical equivalence over the original domain.

Candidates, pinned for independent .NET 10 observation:

- AngouriMath 2.5.0: MIT, https://www.nuget.org/packages/AngouriMath/2.5.0 . Upstream comparisons propose a condition-bearing provided result for rational cancellation; the local runtime must verify this exact contract.
- MathNet.Symbolics 0.25.0: MIT, https://www.nuget.org/packages/MathNet.Symbolics/0.25.0 . Separate F# and MathNet.Numerics >=6.0.0-beta1 dependency graph, not the MathNet.Numerics 5.0.0 already qualified for M3 numerical provider tests. An expression-only C# simplification is not proof that the exclusion x != 1 is retained.
- Explicit out-of-process engine: no package selected, no Python dependency admitted, no executor run performed. Defer unless a required subset or interruption guarantee genuinely calls for it.

These public metadata references are candidates only. A web page is not CLR compilation, runtime provenance, package SHA-256, an owner-approved integration or a license/transitive audit of an actual downloaded artifact.

## T1 bounded independent observation

The AngouriMath direct .NET smoke (tests/providers/m4-w01-c01-angouri/) must:
1. Differentiate x^2-1 with respect to x and simplify the residual against 2*x to zero (rather than comparing pretty-print formatting).
2. Obtain -1 and 1 from its elementary equation solver for x^2-1=0 (without claiming arbitrary real-root solving).
3. Simplify (x^2-1)/(x-1), insist on a visible condition-bearing PROVIDED result, and never treat the reduced x+1 as defined at x=1 without an exclusion.

The separate Math.NET Symbolics direct .NET smoke (tests/providers/m4-w01-c01-mathnet/) must:
1. Differentiate x^2-1 and check f'(3)=6.
2. Verify f(-1)=f(1)=0 only as point evaluations, NOT as an observed equation-solving API.
3. Rational-simplify the quotient and verify x=2 gives 3; explicitly mark exclusion x=1 as NOT qualified by this API. Its simplified expression is not a substitute for a conditional Math result.

Each project has a pinned package reference, an isolated NuGet package cache, no ProjectReference into Math product projects, and an exact success marker. A separate staged C# helper inspects each actually downloaded NuGet package archive for identity, expected MIT metadata, actual direct dependencies, bytes and SHA-256. Math.NET Symbolics must be observed independently of M3 MathNET 5 provider packages.

Compilation/restore failure, absent license expression, wrong equations, or a lost Angouri domain condition must block qualification. A failed candidate is evidence, not permission to claim a selected symbolic runtime.

## Decision, alternatives and deferrals

**Provisional direction, conditional on real RS053 results:** AngouriMath may be selected as the first *candidate* for subsequent IR condition translation, precisely because it is expected to surface provided conditions. MathNet.Symbolics remains a comparison candidate; it is not admitted for unguarded domain-changing cancellation. Out-of-process symbolic execution remains deferred, not an implicit Python runtime requirement.

T1 qualifies only a research/spike decision and explicit observed package bounds. It does NOT create the public symbolics product assembly or its IR bridge. C01-T2 still owns cancellation/interruptibility, bounded node and time budgets, error/status semantics, real-versus-complex assumptions, provider failure and source isolation. C02 must independently prove a typed result retaining x != 1 and refusing evaluation at the excluded point. Never publish provider ASTs or opaque strings as verified mathematical Math IR.

**Review triggers:** version or dependency changes, a conditional result is lost, downstream provider runtime mismatch, a non-cooperative engine violates resource budgets, or Math IR cannot encode the exact exclusions/assumptions.
