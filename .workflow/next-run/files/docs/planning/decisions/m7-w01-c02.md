# M7-W01-C02-T1 — bounded tensor shape and advanced-structure research

## Question

Which tensor or multidimensional-array capability is actually missing from Math's admitted scalar, matrix, and finite numerical contracts? What independently checkable shape, memory, layout and invalid-input examples would justify a future advanced tensor API without copying an application execution engine or adopting a provider prematurely?

## Observation

The prior M7 C01 precision/interval research phase is completed by an explicit *provider deferral*, not by a new numerical runtime. `docs/planning/evidence/M7-W01-C01-T2-qualified.json` retains source/rights/cost gates. No automatic arbitrary-precision or interval backend may be introduced to justify tensor work.

The **independent BCL-only reference**, `docs/planning/ValidateM7TensorAdmission.cs`, checks a finite shape `[2,2,2]`, eight row-major scalar samples `[1,2,3,4,5,6,7,8]`, exact aggregate `sum = 36`, and the zero-based cell `[1,0,1] = 6`. The explicit offset is `((i*shape[1])+j)*shape[2]+k`. This is a small, hand-checkable storage oracle, **not** a delivered tensor object or a general array engine.

The independent negative cases forbid:
- treating `[2,2,2]` and `[2,4]` as shape-compatible merely because both contain eight cells; **no implicit broadcasting, reshape or copy** is admitted;
- a zero extent or invalid rank;
- a request for `[4,4,5]` (80 scalar cells) against a declared **64-element / 512-byte** research cap, while `[4,4,4]` is exactly at the cap;
- oversized dimensions where multiplication would exceed the cap: reject before any allocation instead of overflowing an element count.

The BCL reference provides an exact integer indexing/count witness and bounded rejection behavior for these inputs. It does **not** demonstrate sparse tensor algorithms, automatic differentiation, batched matrix products, layout interoperability, binary64 error bounds, GPU or native providers. `docs/planning/decisions/m7-w01-c02-provider-screen.md` distinguishes these candidate responsibilities and marks third-party providers as not qualified.

## Decision

**Admit research fixtures only** for the bounded dense shape/row-major interpretation, independent reference sum/index and typed-policy refusal criteria. Retain existing Math numerical and matrix contracts, without advertising a new public tensor API, adding `dw.tools.math.advanced`, installing a library or assuming downstream consumption. **No product Tensor API** or new numerical package is delivered by T1.

The conditional *candidate* for the separate T2 decision is an explicit rank/shape/stride/element-type/element-budget contract with no silent allocation, broadcast, transpose, reshape, sparse conversion or native fallback. Any implementation needs a named consumer, actual operation/domain and a new DWF acceptance gate. A research spike can conclude with explicit deferral; research completion does not mean a Tensor API is delivered.

## Alternatives, costs and owner boundary

- Do not embed AURA resource scheduling, agent/job orchestration, chart rendering or GPU/native drivers in Math.
- Do not infer arbitrary-precision, certified interval results or automatic physical-unit compatibility from the C01 spike.
- Do not select tensor or ML providers from their names; require version/source SHA, license/notices, transitive/native dependencies, runtime and target RID, offline smoke and independent source-free consumer checks.
- The T1 cost is one local C# read-only fixture program, two English documents and structural DWF checks. No broad benchmarks, external provider installation, full solution retest, public package or sibling modification is needed for this documentary research task.

## Next action — T2

Evaluate demonstrated consumer need, rank and shape contracts, finite memory/CPU caps, immutable provider/API identity, negative shape/overflow/cancellation outcomes, semver and rights/notices, and independent consumer proof; **admit a justified limited contract or defer with a clear trigger**. Preserve the separation between mathematical data representation and graphical rendering.

**Lifecycle after T1:** M7 and M7-W01 remain in-progress, C02 becomes in-progress, T1 Question/Observation/Decision becomes done, and C02-T2, C02 parent completion, C03, W02 and M7 release gate remain open.
